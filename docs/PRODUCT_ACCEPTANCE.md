# 万象产品闭环与验收标准

本文把万象从实验仓库推进到可被首次用户理解、操作、验证和分享的产品所需事项，拆成可验收的交付门槛。它补充而不替代工程路线图、能力闭环审计和实验内核说明。

## 产品定义

**万象是一个可复现的世界模拟与规则实验平台。** 它以 Rust 世界模型为计算底座，用固定种子、显式规则、tick、结构化事件和状态快照，支持基准轨迹与规则干预轨迹的成对比较。Agent 是可以参与世界的可选执行者，不是万象本身；大模型不是运行确定性模拟所必需的依赖。

第一阶段的核心用户是需要构建虚拟世界、测试模拟规则，或评估 Agent 行为的开发者。互动叙事是一个演示场景，不应掩盖主产品承诺：**同一份实验规格应可检查、可比较、可导出，并能在兼容版本中复现。**

## 首次体验：无需后端

从 GitHub Pages 打开在线实验室时，默认路径无需登录、Rust 工具链、模型密钥或实时 API：

1. 页面自动加载由 wanxiang_sdk::WorldModel 在构建时生成的基准世界与规则变体。
2. 用户切换基准世界/规则变体，查看指标、规则、世界结构、地点、势力和事件时间线。
3. 用户导出版本化的对照实验 JSON；该操作仅在浏览器本地构建文件，不向服务器上传快照。
4. 用户可以把报告文件交给他人检查；接收者可用导入功能打开支持的比较包或快照。
5. 实时 Rust API 的连接状态与静态演示状态明确区分。没有后端时，静态浏览与报告导出仍可用；需要实际推进世界、执行写操作或运行 Agent 时才要求实时 API。

## 对照实验报告契约

静态实验室导出使用版本化 envelope；下游工具可用 schemas/wanxiang-experiment-report-v1.schema.json 校验格式：

- format 固定为 wanxiang-experiment-report-v1，schema_version 当前为整数 1。
- generated_at、generated_by、source 记录生成时间、导出器和输入来源。
- build 保留静态演示的来源修订信息；本地或旧样例不可得时使用 null。
- scenario 原样保留 SDK comparison payload 的实验元数据。
- experiment 汇总 seed、tick、改动规则、前后规则值，以及两条轨迹是否具有相同 seed 和 tick。
- baseline、altered 完整保留成对世界快照；diff 保留 SDK 提供的结构化差异。
- interpretation 明确实验结果适用范围与回放限制。

导出动作应满足：只有同时拥有基准和变体的比较数据时按钮才可用；报告保留真实快照而不是只导出 UI 四舍五入指标；如果无法得到规则元数据，不应编造。报告是可离线检查的比较档案，不等同于含完整操作历史的 wanxiang-replay-v1 checkpoint。结果只支持对当前模拟模型作解释，不证明现实世界预测准确性或现实因果效应。

## 自动化验收矩阵

| 层级 | 必须验证 | 验收状态与边界 |
|---|---|---|
| 静态数据生成 | 固定 seed、tick 与不同规则值 | CI 生成真实 SDK 数据并校验 metadata、diff 与账本不变量 |
| 静态首用路径 | 无 API 加载样例、切换比较分支、导出报告 | 浏览器 E2E 覆盖默认样例、导出、重新导入、规则差异与无效输入禁用导出 |
| 结构化展示 | 世界/势力、地点驻地、事件时间线 | 浏览器 E2E 检查地点关系与交互；未声明的经纬度/真实地理含义不应推断 |
| 实时 API | 健康检查、手动推进、规则实验隔离 | evaluator 检查 API 边界、实验重放确定性和源世界不变性 |
| 状态可靠性 | checkpoint、幂等、重启恢复、持久化降级 | CI 含重启恢复、重复请求和持久化故障注入检查 |
| 资源与行动 | 旅行计划、旅行执行、采矿、交易、生产 | 浏览器和 Rust 测试检查只读计划、状态变化、事件与已声明账本不变量 |
| Agent 评测 | 无记忆、记忆、记忆加因果图 | 基准脚本先校验三组 seed、起始 tick 和完整初始快照，再运行任务并记录成功、工具错误、步数、平均/P95 延迟与状态是否改变 |
| 部署配置 | 真实域名、强 Token、精确 CORS origin、可选模型配置完整性 | validate-live-deployment-env.py 的离线单元测试不需要生产密钥；生产环境配置仍须在目标主机手动验收 |
| 发布 | 根工作区、engines/、容器、浏览器 E2E | 以最新 main CI 和 Pages 部署结果为准；不得将容器构建成功等同于公共 API 已上线 |

## 浏览器验收

当前真实浏览器端到端脚本为 scripts/test-world-renderer-browser.cjs。现有 CI 实施以下检查：

- [x] 页面自动加载默认 SDK 样例。
- [x] 在未连接 API 时导出 wanxiang-experiment-report-v1，并重新导入报告继续比较。
- [x] 报告 seed、tick、baseline/altered 快照、diff、build metadata 与解释边界满足契约。
- [x] 基准/变体切换、地点网络、路径高亮、缩放等交互可用。
- [x] 连接实时 API 后，执行只读旅行规划和实际旅行并检查状态变化。
- [x] 导出 checkpoint 包，并通过压缩离线分享链接加载世界；离线页面不会重新连接导出端的 API。
- [x] 浏览器运行时没有未捕获的 page error。

上述自动化结果应以当前分支/主分支最新 CI 记录为准。代码存在或肉眼查看不等于验收通过；本分支新增的测试还需通过新的 PR CI。

## Agent 评测协议

运行 scripts/benchmark-agent-modes.py 时，三个实例需使用隔离的数据目录、相同 seed、相同 tick、相同世界 preset/type、相同任务和相同 provider/model，并将 WANXIANG_TICK_MS 设置为 0。基准涵盖只读观察任务以及在独立实验分支执行规则对照的任务。

脚本会在第一次 Agent 调用之前完成三组健康状态检查，并强制检查：

- 三种模式分别对应 no-memory、memory、causal，Agent provider 均已配置，自动 tick 关闭且持久化未降级。
- 三个初始世界的 seed、tick 与完整快照摘要均一致；支持显式传入 expected seed/tick。发现不一致时必须在任何 provider 调用前终止。
- 每个任务前后比较源世界快照，统计任务成功率、工具失败步数、工具调用步数、平均/P95 延迟和源世界不变比例。
- JSON 报告记录运行开始/结束时间、run ID、seed/tick、初始快照 SHA-256、任务明细，以及操作员声明的 provider/model label。

Provider/model label 是人工填写的元数据，不由服务端认证；报告不测量实际账单或 token 用量，需从 provider 控制台单独核对。该基准实际调用模型，可能产生费用，因此 CI 只运行不收费的本地单元测试，不自动执行完整的模型 A/B 测试。合成任务的表现不证明通用智能或记忆语义质量。若声称记忆优于基线，还需要带标签的真实任务集，并与关键词、BM25、向量检索等基准比较。

## 实时 API 部署验收

部署和运维步骤见 docs/OPERATIONS_RUNBOOK.md。scripts/validate-live-deployment-env.py 在部署前检查域名、Token 强度、精确 CORS origin、模型设置成组完整性与 tick/seed 格式；脚本不会打印凭据。它不能替代 DNS、TLS、外部网络路径和目标主机实际服务的检查。

在公开声明“已可供外部用户实时使用”之前，必须在真实域名/主机上完成 HTTPS、认证和 readiness 验收，并落实用户级授权、限流/配额、集中日志与告警、备份恢复、provider 超时/限额与费用治理。当前共享 bearer token 的自托管服务属于受控 beta，不是完整的多租户 SaaS。仓库里没有生产服务器、DNS 权限或生产密钥，所以自动化构建不应被描述成已公开部署。

## 不做的承诺

万象不应把以下事项作为既成事实：真实世界因果推断、经过校准的风险概率、语义级记忆理解、生物意义上的生命或意识、操作系统级安全沙箱、跨版本永久兼容的回放。任何更强的表述都需要独立的规格、数据和可复现评估支持。
