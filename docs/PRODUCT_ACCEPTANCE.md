# 万象产品闭环与验收标准

本文把万象从实验仓库推进到可被首次用户理解、操作、验证和分享的产品所需事项，拆成可验收的交付门槛。它补充而不替代 [工程路线图](ROADMAP.md)、[能力闭环审计](CAPABILITY_CLOSURE_AUDIT.md) 和 [实验内核说明](EXPERIMENT_KERNEL.md)。

## 产品定义

**万象是一个可复现的世界模拟与规则实验平台。** 它以 Rust 世界模型为计算底座，用固定种子、显式规则、tick、结构化事件和状态快照，支持基准轨迹与规则干预轨迹的成对比较。Agent 是可以参与世界的可选执行者，不是万象本身；大模型不是运行确定性模拟所必需的依赖。

第一阶段的核心用户是需要构建虚拟世界、测试模拟规则，或评估 Agent 行为的开发者。互动叙事是一个演示场景，不应掩盖主产品承诺：**同一份实验规格应可检查、可比较、可导出，并能在兼容版本中复现。**

## 首次体验：无需后端

从 GitHub Pages 打开在线实验室时，默认路径必须无需登录、Rust 工具链、模型密钥或实时 API：

1. 页面自动加载由 wanxiang_sdk::WorldModel 在构建时生成的基准世界与规则变体。
2. 用户切换“基准世界 / 规则变体”，查看指标、规则、世界结构、地点、势力和事件时间线。
3. 用户导出“万象可复现规则对照实验报告” JSON；该操作仅在浏览器本地构建文件，不向服务器上传快照。
4. 用户可以把报告文件交给他人检查；接收者可用“导入自己的 JSON”打开支持的比较包或快照。

实时 Rust API 的连接状态必须与静态演示状态明确区分。没有后端时，静态浏览与报告导出仍应可用；需要实际推进世界、执行写操作或运行 Agent 时才要求实时 API。

## 对照实验报告契约

静态实验室导出使用以下版本化 envelope：

- format：固定为 wanxiang-experiment-report-v1。
- schema_version：当前为整数 1。
- generated_at、generated_by、source：记录生成时间、导出器和输入来源。
- scenario：原样保留 SDK comparison payload 的实验元数据。
- experiment：汇总 seed、tick、改动规则、前后规则值，以及两条轨迹是否具有相同 seed 和 tick。
- baseline、altered：完整保留成对世界快照。
- diff：保留 SDK 提供的结构化差异。
- interpretation：明确实验结果适用范围与回放限制。

导出动作应满足：

- 只有同时拥有基准和变体的比较数据时按钮才可用；导入单个快照时应禁用。
- 文件可由严格的 JSON parser 读取，文件名包含 seed 与 tick。
- 报告保留真实快照与差异，而不是只导出 UI 中显示的四舍五入指标。
- 若无法从输入得到规则元数据，字段应为 null 或显式空值，不应编造。
- 报告是可离线检查的比较档案，不等同于含完整操作历史的 wanxiang-replay-v1 checkpoint。需要重新计算时，必须有兼容的 SDK 版本和足够的原始规格/操作记录。
- 结果只支持对当前模拟模型作解释，不证明现实世界预测准确性或现实因果效应。

## 自动化验收矩阵

| 层级 | 必须验证 | 通过条件 |
|---|---|---|
| 静态数据生成 | 固定 seed、tick 与不同规则值 | demo JSON schema 校验成功，两条快照 seed/tick 匹配，改动规则不同 |
| 静态首用路径 | 无 API 加载样例、切换比较分支、导出报告 | 首次访问不要求 API；下载的 JSON 具有版本、场景、两份快照与 diff |
| 结构化展示 | 世界/势力、地点驻地、事件时间线 | UI 使用导出的实体关系；地点网络不虚构地理位置或路线 |
| 实时 API | 健康检查、手动推进、规则实验隔离 | 请求边界有效；实验不修改在线基线；无效参数不推进 tick |
| 状态可靠性 | checkpoint、幂等、重启恢复、持久化降级 | 测试能够检测重复 POST、恢复失败与 readiness 降级 |
| 资源与行动 | 旅行计划、旅行执行、开采、交易、生产 | 只读计划不改变状态；实际操作有事件记录，并满足声明的账本不变量 |
| Agent 评测 | 无记忆、记忆、记忆加因果图 | 同任务/seed 配对；报告成功率、工具错误、步数、均值/P95 延迟和基线是否被意外修改 |
| 发布 | 根工作区、engines/、容器、浏览器 E2E | 干净 checkout 的相关 CI 全绿；失败的 job 必须修复或明确列为发布阻断项 |

## 合并前的浏览器验收

现有端到端脚本为 scripts/test-world-renderer-browser.cjs。它启动后应验证至少以下静态与实时行为：

- [ ] 页面自动加载默认 SDK 样例。
- [ ] 在未连接 API 时成功导出 wanxiang-experiment-report-v1 文件。
- [ ] 报告 seed、tick 与生成数据一致，baseline / altered 均存在，且保留结构化 diff 和使用边界。
- [ ] 基准/变体切换能更新 UI，地点和事件时间线可交互。
- [ ] 连接实时 API 后，读取世界、规划旅行和实际旅行的结果与状态变化符合预期。
- [ ] checkpoint 回放导出、离线分享链接加载和状态重启恢复通过。
- [ ] 浏览器无未捕获的运行时错误。

新增测试在 CI 通过后再将相应清单标为已完成；代码存在或本地肉眼查看并不等于验收通过。

## Agent 评测协议

运行 scripts/benchmark-agent-modes.py 时，每个模式必须使用隔离的数据目录、相同 seed、相同任务、相同 provider/model 与 WANXIANG_TICK_MS=0。基准包括只读观察任务和独立分支中的规则对照任务。报告至少应包含：

- 任务成功率与源世界未被改变的比例；
- 工具错误步数、平均工具调用步数；
- 平均与 P95 延迟；
- 每种模式的请求数、模型与配置说明，并记录是否产生费用。

这个基准当前会调用配置的模型 provider，可能产生费用；不得在无预算/配额约束下自动运行。合成任务的表现不能证明通用智能或记忆语义质量。若要声称记忆优于基线，还需要有标签的真实任务集，并和关键词/BM25/向量检索等基准比较。

## 发布门槛与不做的承诺

在公开声明“已可供外部用户实时使用”之前，必须完成真实域名、HTTPS、认证、按用户授权、限流、日志与告警、备份恢复、provider 配额/超时与费用治理。当前共享 bearer token 的自托管服务属于受控 beta，不是完整的多租户 SaaS。

万象不应把以下事项作为既成事实：真实世界因果推断、经过校准的风险概率、语义级记忆理解、生物意义上的生命或意识、操作系统级安全沙箱、跨版本永久兼容的回放。任何更强的表述都需要独立的规格、数据和可复现评估支持。
