# 万象路线图

本文以 `main` 中已合入的实现为基线，区分“代码存在”“自动化验证通过”和“对外服务已部署”。某项功能进入仓库不代表它已经达到生产级，也不代表公共在线服务已经提供该功能。

## 当前基线

### 世界模拟与实验

- [x] 使用显式 seed 创建世界、按 tick 推进状态，并导出快照、事件、资源和规则信息。
- [x] 在相同初始条件下构建规则变体，重放公开操作并比较两条模拟轨迹。
- [x] 在静态站展示由 Rust SDK 实际生成的样例数据、世界结构、地点网络、居民、资源、规则、势力与事件流。
- [x] 提供 checkpoint / operation-history 回放包、JSON 导出、离线分享链接及 Rust SDK 验证示例。

### 可行动世界与经济

- [x] 地点拓扑、居民关系、角色路线与确定性寻路。
- [x] 模拟旅行、tick 推进、抽象补给开销及可回放的旅行事件。
- [x] 资源采集、地点库存、势力资源池、市场报价与交易结算。
- [x] 矿点占领、挑战和开采；资源从地点库存转入势力资源池，并由测试检查库存守恒。
- [x] 生产订单、劳动力、投入产出及工资结算。
- [x] Agent bridge 工具覆盖世界查询、移动/旅行，以及采矿等真实模拟操作。

### 工程与发布边界

- GitHub Pages 是静态站。它会在部署工作流中运行 Rust SDK 生成样例数据，不是浏览器里伪造的随机模拟。
- 静态样例支持查看与规则比较；要真实推进世界或执行写操作，需要连接单独运行的 Rust API。
- 仓库带有容器和部署配置，但配置文件存在不等于公共服务已上线。**当前没有由仓库默认配置提供的公共实时 API。**
- 根 Cargo 工作区与 `engines/` 是独立工作区；部分因果、记忆、LLM 和安全模块仍属于研究组件。具体集成边界以 [能力闭环审计](CAPABILITY_CLOSURE_AUDIT.md) 为准。
- 所有外部发布声明以最新 main CI、浏览器验收和部署工作流的结果为准，不以单个功能分支通过代替主分支验收。

## 下一阶段优先级

### P0 — 发布与首次体验

- [ ] 确保 main 上 Rust workspace、引擎工作区和容器任务全部通过；跟进失败或长期挂起的任务。
- [ ] 将首页的静态演示与实时 API 两种模式区分清楚，避免“API 未连接”被理解为页面无法使用。
- [ ] 给第一次打开的用户提供明确的静态体验路径：观察基准世界、切换规则变体、检查差异与事件。
- [ ] 通过真实浏览器 E2E 验证静态模式可以离线导出版本化对照实验报告；报告须包含场景、两份完整快照、结构化 diff 与局限说明。
- [ ] 在合并后重新验收 Pages 生成的 JSON、页面脚本和浏览器集成测试。
- [ ] 更新 README、路线图和在线演示说明，确保功能状态与实际主分支一致。

验收标准：干净访客无需配置环境即可查看默认世界和规则差异，并在不连接 API 时导出有效的对照实验报告；实时操作在 API 未连接时有清楚说明；静态部署构建成功；主分支 CI 全绿。

### P1 — 稳定性与可维护性

- [ ] 给 SDK 的公开接口建立稳定性分级、版本迁移策略和端到端示例。
- [ ] 维护跨 seed、多个 tick horizon 的回放一致性、资源守恒和规则对照基线。
- [ ] 记录常用世界规模的构建时间、tick 吞吐、内存峰值和浏览器渲染成本。
- [ ] 明确抽象旅行补给、地点资源库存、交易和生产之间尚未联动的规则边界，避免把不同账本误称为一个守恒系统。
- [ ] 为 Agent 目标、观察、计划、审批、执行和结果验证建立统一的任务级评测。

### P2 — 对外实时服务

- [ ] 如需公开多人或跨用户实时体验，部署有真实域名、TLS、认证、速率限制、日志与备份的独立 API。
- [ ] 完成对持久化降级、并发写入、幂等键、凭据轮换和恢复流程的运维演练。
- [ ] 实测目标 LLM provider 的超时、限额、重试、流式响应和费用控制；仅有接口适配不能作为服务可用的证据。

## 非目标与声明边界

- 模拟可复现不代表模拟规则符合现实，也不自动产生现实预测能力。
- 规则干预比较只解释当前模型内的轨迹差异，不等于现实世界中的因果效应证明。
- 资源账本的守恒不等于物理能量守恒；旅行风险分数不等于校准概率。
- 2.5D SVG 地点网络不等于通用 3D 地图引擎。
- 因果图、记忆检索和 Agent 工具的实现不等于生产级通用智能体或安全沙箱。
