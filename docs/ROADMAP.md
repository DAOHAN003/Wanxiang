# 万象路线图

本文以 main 中已合入的实现为基线，区分“代码存在”“自动化验证通过”和“对外服务已部署”。某项功能进入仓库不代表它已经达到生产级，也不代表公共在线服务已经提供该功能。

## 当前基线

### 世界模拟与实验

- [x] 使用显式 seed 创建世界、按 tick 推进状态，并导出快照、事件、资源和规则信息。
- [x] 在相同初始条件下构建规则变体，重放公开操作并比较两条模拟轨迹。
- [x] 在静态站展示由 Rust SDK 实际生成的样例数据、世界结构、地点网络、居民、资源、规则、势力与事件流。
- [x] 提供 checkpoint / operation-history 回放包、JSON 导出、离线分享链接及 Rust SDK 验证示例。
- [x] 静态实验室可在不连接 API 时导出版本化的对照实验报告，并用 JSON Schema 与 Python 校验器验证其结构。

### 可行动世界与经济

- [x] 地点拓扑、居民关系、角色路线与确定性寻路。
- [x] 模拟旅行、tick 推进、抽象补给开销及可回放的旅行事件。
- [x] 资源采集、地点库存、势力资源池、市场报价与交易结算。
- [x] 矿点占领、挑战和开采；资源从地点库存转入势力资源池，并由测试检查库存守恒。
- [x] 生产订单、劳动力、投入产出及工资结算。
- [x] Agent bridge 工具覆盖世界查询、移动/旅行，以及采矿等真实模拟操作。

### 工程与发布边界

- GitHub Pages 是静态站。部署工作流会运行 Rust SDK 生成样例数据，不是浏览器里伪造的随机模拟。
- 静态样例支持查看与规则比较；要真实推进世界或执行写操作，需要连接单独运行的 Rust API。
- 仓库带有容器和部署配置，但配置文件存在不等于公共服务已上线。当前没有由仓库默认配置提供的公共实时 API。
- 根 Cargo 工作区与 engines/ 是独立工作区；部分因果、记忆、LLM 和安全模块仍属于研究组件。具体集成边界以能力闭环审计为准。
- 页面静态部署成功、PR CI 通过与 main 最新 CI 全绿是不同的发布信号；对外声明应以最新 main 验收为准。

## 下一阶段优先级

### P0 — 首次体验与合并验收

- [ ] 确认最新 main 上根工作区、engines/ 工作区与容器任务全部通过；跟进失败或长期挂起的任务。
- [x] 首页明确静态演示无需后端，实时操作需要独立 Rust API。
- [x] 第一次打开即可观察基准世界、切换规则变体并检查指标、地点、势力和事件。
- [x] 静态模式可离线导出版本化对照实验报告；报告保留场景、完整快照、结构化 diff 与局限说明。
- [x] 浏览器 E2E 覆盖报告导出/重新导入、真实 API 下的旅行与检查点导出，以及离线 replay 分享链接。
- [ ] 在本分支新增的 Agent 评测前置检查、部署配置校验单元测试和文档合并后，确认全部 CI 再次通过。

验收标准：干净访客无需配置环境即可查看默认世界和规则差异，并在不连接 API 时导出有效报告；API 未连接时的限制有明确说明；静态部署成功；相关 CI 全绿。

### P1 — 稳定性与可维护性

- [ ] 给 SDK 的公开接口建立稳定性分级、兼容策略和版本迁移示例。
- [ ] 维护跨 seed、多个 tick horizon 的回放一致性、资源守恒和规则对照基线；现有固定 seed benchmark 是起点，不等同于完整覆盖。
- [ ] 对常用世界规模记录构建时间、tick 吞吐、内存峰值和浏览器渲染成本。
- [x] 文档明确旅行补给、地点资源库存、交易和生产等账本的边界，不把尚未联动的量误称为一个统一守恒系统。
- [x] 增加三种 Agent 检索模式的任务级评测工具；在首次模型调用前校验三种模式的 seed、tick 和完整初始快照一致，记录工具错误、成功率、延迟和世界状态是否改变。
- [ ] 在有明确预算和真实 provider 配置的环境中运行 Agent 模式对比；当前自动化单元测试不会调用付费模型，代码/协议存在不等同于某种记忆模式更优。

### P2 — 实时 API 对外服务

- [x] 提供自托管实时 API 的环境预检脚本，检查域名、强 Token、精确 CORS origin、可选 LLM 配置完整性及 tick/seed 格式。
- [x] 补充部署和运维手册，覆盖 HTTPS、认证、健康/ready 验收、备份、恢复、Token 轮换与故障处理。
- [x] 为 Agent、实验、LLM 流式请求和会话驱动配置实例级路由限流；PR 分支 CI 已通过限流集成测试、两个 Rust 工作区、浏览器 E2E 与容器 smoke test。此限流仍是实例级，不是用户级或跨实例配额。
- [ ] 若要公开多人或跨用户实时体验，需在真实主机与域名上完成部署，并另外实现/验证用户级授权、跨实例配额协调、集中日志、告警与备份恢复。
- [ ] 完成真实部署中的持久化降级、并发写入、幂等键、凭据轮换和恢复演练；现有 CI 故障注入测试不能代替生产数据上的恢复演练。
- [ ] 在目标 LLM provider 上实际测量超时、额度/限额、重试、流式能力和费用；仅有接口适配不能作为服务可用证据。

部署入口见实时 API 部署与运维手册。仓库没有用户提供的生产主机、DNS 管理权限或生产密钥，因此不会把 CI 容器成功描述为公共 API 已上线。

## 非目标与声明边界

- 模拟可复现不代表模拟规则符合现实，也不自动产生现实预测能力。
- 规则干预比较只解释当前模型内的轨迹差异，不等于现实世界中的因果效应证明。
- 资源账本的守恒不等于物理能量守恒；旅行风险分数不等于校准概率。
- 2.5D SVG 地点网络不等于通用 3D 地图引擎。
- 因果图、记忆检索和 Agent 工具的实现不等于生产级通用智能体或安全沙箱。
