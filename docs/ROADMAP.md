# 万象路线图（工程交付版）

本文区分稳定基线、功能分支实现和可发布状态。只有代码、回归测试与 CI 都通过，才标记为完成。当前功能仍在 `feat/world-movement-actions-v2` / PR #16 的堆叠分支中；未合并，不等于线上已部署。

## 当前基线

- **世界内核：** Rust seed 驱动的确定性模拟，按 tick 推进；导出角色、势力、地点、事件、资源与规则快照。
- **规则实验：** 固定 seed / horizon 下比较基准与规则干预，输出结构化差异和不变量检查。
- **Web 实验室：** 静态快照与独立实时 Rust API 两种模式；SVG 关系网络、地点空间投影、居民、事件时间线和规则差异视图。GitHub Pages 本身不运行后台模拟。
- **当前分支：** 移动、最小代价路线、旅行规划预览、旅行时间/风险/补给/遭遇、快照回放、Agent 工具和浏览器验收工件；所有这些改动仍须由最新 CI 验证并按 PR13 → PR14 → PR15 → PR16 顺序处理。

## P0 — 行动闭环和持久化

- [x] SDK 对直连移动和多段旅行进行边验证、事件记录与 checkpoint/fork/branch 确定性回放测试（当前分支实现，CI 待确认）。
- [x] 实时 API 支持 `POST /api/move`（即时移动）和 `POST /api/travel`（推进 tick 的模拟旅行），突显错误和幂等行为。
- [x] 添加进程重启验收：旅行后的世界 tick、补给预算和重复请求缓存应恢复一致（当前分支测试，CI 待确认）。
- [x] Playwright 真实浏览器测试执行“连接 API → 预估旅行 → 确认状态未变 → 执行旅行 → 比较快照/路线高亮”；同时收集实际截图和大世界渲染记录（当前分支测试，CI 待确认）。
- [ ] 按 PR13 → PR14 → PR15 → PR16 依赖顺序审查、合并，并验证合并后的 CI。
- [ ] 重跑 Pages 部署工作流，验收静态站的空状态、真实地点连接及构建产物。

验收门槛：旅行预览不改变世界；无效路线/补给不足不会部分移动；已执行旅行可确定性回放；相同 `Idempotency-Key` 不会重复花费补给或重复推进。

## P1 — 空间数据与路径规则

- [x] 地点可选本地 `(x, y, elevation)`、地形和显式基础旅行成本；老快照兼容缺省字段。
- [x] 区分作者配置坐标与 seed 派生布局坐标；二者均不代表真实经纬度或地理距离。
- [x] 路线代价加入水平距离、高差、危险度、地形标签和地点基础成本；角色 power rank 按明确上限降低危险项。
- [x] 路线规划固定精度量化成本，并以成本、hop 数和完整路径字典序稳定打破平局。
- [x] 旅行估算与执行共享同一确定性计划；展示预计 tick、风险分数、预测遭遇、补给需求、可承担状态及缺口。
- [ ] 若未来引入真实地图数据，单独定义坐标参考系、边方向、单位、地图投影及迁移版本；不得复用抽象坐标假装地理数据。

注意：风险值是模型内的暴露分数，不是校准过的现实概率；补给目前是独立的抽象旅行预算，不等同于地点库存，也没有计入守恒能量账本。

## P2 — 可用的 2.5D 地点网络

- [x] 本地坐标与高程影响 SVG 投影；检查器展示坐标、地形、危险、资源和居民。
- [x] 最近旅行路线动态高亮，并支持缩放；遵循 `prefers-reduced-motion` 的用户偏好。
- [x] 为节点渲染加固定上限（240 个节点）以避免大世界一次性建立无限 SVG DOM，并在 UI 显示当前渲染数 / 总数。
- [x] Playwright 验收生成截图与 5,000 地点的渲染耗时记录（CI 通过后才算验证完成）。
- [ ] 真正的多边形地形面、纹理/图例和视口级裁剪仍待做；当前做的是节点规模上限，不是完整地图引擎。
- [ ] 在多个浏览器与固定硬件上做缩放、可访问性和响应式性能基准；暂不承诺完整 3D 地形。

## P3 — 旅行与世界后果

- [x] 旅行时间推进世界 tick；按路程、高差、地点危险/地形和角色能力生成确定性风险评估。
- [x] 旅行花费抽象补给，风险判定产生可重放遭遇事件；预算不足在出发前拒绝。
- [ ] 将补给预算与真实地点资源、贸易库存和角色携带容量连接，并为资源流入/流出定义守恒规则。
- [ ] 加入地点控制、贸易价格/路径、外交与战争的可测量状态转移；明确哪些字段变化、事件和不变量应发生。
- [ ] 建立多 seed、多规模与长 horizon 的压力测试，记录吞吐、tick 延迟、内存峰值、守恒漂移和 digest。

## P4 — Agent 规划和评估

- [x] 为 Agent 区分只读 `world_plan_travel` 与有副作用的 `world_travel_character`；规划会返回路径、耗时、风险、预测遭遇和预算可行性。
- [ ] 将“目标 → 观察 → 提案 → 估算 → 按审批策略执行 → 验证结果”沉淀成统一任务协议，并测试中断与恢复。
- [ ] 为任务完成率、路径成本、供给开销、工具错误和跨 seed 稳定性建立机器可读评测集。
- [ ] 对 provider 的 TLS、429、超时、断流、重试和 SSE 进行独立实测；接口契约测试不等同于外部 provider 已可用。

## P5 — 部署与运维

- [x] 服务默认回环绑定；公开绑定要求 bearer token，提供来源限制配置、健康/ready 检查和非 root 容器测试。
- [x] 世界检查点、Agent 记忆与 resumable session 支持原子保存/恢复；测试持久化降级和请求幂等（CI 待确认）。
- [ ] 对公开 API 补充身份/租户模型、每主体限额、速率限制、审计和可撤销凭据。
- [ ] 增加备份保留/演练、并发写冲突、TTL 迁移、负载与故障注入测试和运行指标。
- [ ] 公开长期运行实例需要真实的托管环境、域名、TLS 与密钥管理；当前不能把静态 Pages 描述成实时服务，也不能把未获凭据的环境宣称已部署。

## 下一步优先级

先让 PR16 的 Rust、持久化 API、浏览器和容器 CI 全绿，再沿堆叠顺序合并。之后优先实现补给与地点库存的明确规则、贸易/地点控制的状态转移、Agent 任务协议和跨 seed 评测；只有空间数据语义与性能预算稳定后，才决定是否升级为完整 3D。
