# 万象路线图（工程交付版）

本文区分已存在的能力、当前开发分支中的能力和后续计划。功能只有在代码、回归测试和 CI 三方面成立时，才算完成；路线图、静态示意和组件存在本身不等于交付。

## 当前基线

- **世界内核：** Rust seed 驱动模拟，按 tick 推进，导出状态、角色、势力、地点、事件和资源账本。
- **规则实验：** 同 seed、同 horizon 下比较基准规则与单项干预，输出结构化差异及不变量结果。
- **Web 实验室：** 静态网页读取 Rust SDK 构建时导出的 JSON；2D SVG 展示角色—势力关系、地点连接、贸易/战争边和事件时间线。静态 Pages 不运行后台模拟。
- **Agent 研究链路：** 有受限工具执行、快照观察、记忆回写、规则实验以及可选 LLM adapter；外部 provider 的 SLA、真实流式传输、限额和重试仍需部署级验证。
- **当前工作分支新增：** 角色移动、确定性最短路旅行、逐段事件、checkpoint/fork/branch 回放、API 端点和网页控件。这个功能分支还需 CI 确认并按 PR 堆叠关系合并，未合并前不能宣称已发布。

## 交付顺序

### P0 — 让行动闭环可验收

目标：从“看到路线图”变成“角色真的走过路线，页面与历史同步”。

- [ ] 让 SDK 移动与寻路测试通过：边验证、未连通路线拒绝、每段事件、相同 seed 回放一致。
- [ ] 让 Agent 工具测试通过：规划动作 → 调用 travel 工具 → 读回快照 → 下一轮决策看到真实结果。
- [ ] 让 `POST /api/move` 与 `POST /api/travel` 通过幂等测试；非法路线不可改变位置或追加事件。
- [ ] 用真实浏览器自动化测试检查连接状态、角色/目的地列表、执行旅行、节点位置变化和错误状态。当前 CI 的 HTML/JS 检查不等于浏览器端到端测试。
- [ ] 按依赖顺序完成 PR13 → PR14 → PR15 → 路线移动 PR 的审查、合并与 CI。
- [ ] 重跑静态 Pages 工作流，验证实际部署产物包含有效地点、有效道路、角色驻地，以及可工作的空状态。

**验收门槛：** 固定 seed 重建后得到完全相同的移动事件序列；重复同一个 Idempotency-Key 不会重复执行；无效路线返回明确错误且快照字节级不变；浏览器实际点选后能看到变化。

### P1 — 建立真实的空间数据模型

目标：为地图和 2.5D 渲染提供有明确语义的世界坐标，而不是从图形布局伪装成地图。

- [ ] 为地点增加可选本地坐标 `(x, y, elevation)`、地形/生境标签和坐标版本。
- [ ] 区分**作者明确配置的坐标**与**seed 派生的抽象布局坐标**。两者都不是现实地理坐标，除非另有真实地图数据。
- [ ] 让预设地点能够声明坐标和地形；旧预设缺少空间字段时使用兼容的确定性布局，不能改变既有 RNG 序列。
- [ ] 将坐标/地形加入导出快照，并对坐标边界、同 seed 稳定性、缺失值和未知引用做 schema 测试。
- [ ] 从等权最短路升级到可解释的路径代价：边长、高差、地形、危险度和角色能力；所有代价都要有显式规则和测试。
- [ ] 定义旅行耗时、风险、补给/资源消耗，以及途中中断/遭遇事件的规则，不把“画一条线”当成完成的旅行模拟。

### P2 — 交付 2.5D 空间渲染

目标：先实现能够读懂的可交互地形图，再评估是否需要完整 3D。

- [ ] 以本地坐标投影地点和道路；高差影响投影高度/分层，地形用可访问的颜色、形状和图例表达。
- [ ] 展示居民/队伍图标、选中态、路径高亮、旅行中的角色和地点信息侧栏。
- [ ] 将鼠标/键盘交互、缩放、选择、筛选和移动反馈接入真实快照，不用静态插图代替 live 数据。
- [ ] 对大世界建立视口裁剪/聚合策略，并用固定世界规模做帧率及渲染性能测量。
- [ ] 增加 Playwright 浏览器测试和一份可复现的截图工件；截图必须来自实际运行的构建，不是概念图。

### P3 — 让世界规则产生有意义的后果

目标：让角色行动不是单纯改变一个字段。

- [ ] 角色移动与地点危险/资源、路程、高差、补给和旅行耗时发生可测量的相互作用。
- [ ] 定义可检验的贸易、外交、战争、人口迁徙与地点控制规则，明确每个规则会修改哪些状态。
- [ ] 建立长期模拟基准：多个 seed、不同世界规模、长 horizon 的不变量、稳定性和性能报告。
- [ ] 将规则干预扩展到旅行/资源机制，给每次实验保存输入 spec、seed、输出 digest 和可重现命令。
- [ ] 将“守恒账本”“因果干预”“记忆检索”等概念限定在有测试支持的模型语义之内；不把模拟内相关性说成现实因果证明。

### P4 — Agent 规划与评估

目标：从“能调用工具”走到“行动质量可测”。

- [ ] 为 Agent 定义结构化目标、观察、可执行动作、终止条件和失败恢复协议。
- [ ] 旅行规划读取地点连通性、路径代价和危险度，先提出计划，再按审批策略执行。
- [ ] 为记忆检索和因果启发式建立带标签评测集，与关键词/无记忆/随机策略基线比较。
- [ ] 对任务成功率、每步工具错误、路径成本、资源开销和长程漂移输出机器可读评测。
- [ ] 实测多个 OpenAI-compatible provider 的 TLS、超时、429、断流、重试、SSE 和 JSON 严格解析；核心契约通过不等于 provider 运行成功。

### P5 — 可控部署

目标：把个人实验服务与公开服务明确区分。

- [ ] 完成身份认证、每用户授权、速率限制、额度、可撤销令牌和审计追踪。
- [ ] 为世界状态、Agent 记忆和 resumable session 增加备份/恢复、TTL、并发冲突处理和迁移策略。
- [ ] 对公开运行的 API 增加负载、故障注入、恢复演练和资源上限测试。
- [ ] 将健康检查、持久化降级、tick 延迟、模型错误、队列与成本指标接入监控。
- [ ] 在获得实际部署环境和凭据后再发布持续运行服务；GitHub Pages 只承载静态内容，不提供后台世界进程。

## 近期优先级

优先完成 **P0 的移动闭环和真实浏览器验收**，同时把空间坐标 schema 作为 P1 的第一个独立、可回滚改动。P2 的 2.5D 在坐标契约稳定后推进。完整 3D 应在有明确地形/视角/性能需求后再决定，避免先建外观、再反向猜测世界数据。
