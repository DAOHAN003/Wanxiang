# Wanxiang Roadmap

This roadmap distinguishes code presence, automated validation, and deployed public services. A feature being present in the repository does not mean it is production-ready or available as a hosted public service.

## Current baseline

### World simulation and experiments

- [x] Create worlds from explicit seeds, advance state by ticks, and export snapshots, events, resource and rule information.
- [x] Build rule variants under matched initial conditions, replay public operations, and compare trajectories.
- [x] Publish a static site showing sample data generated by the Rust SDK at build time.
- [x] Provide checkpoint/operation-history replay packages, JSON export, offline share links, and SDK validation examples.
- [x] Export versioned comparison reports from the static lab without an API connection and validate their structure.

### Actionable world and economy

- [x] Location topology, resident relationships, routes and deterministic pathfinding.
- [x] Travel simulation, tick advancement, abstract supply costs and replayable travel events.
- [x] Resource gathering, location inventories, faction pools, market quotes and trade settlement.
- [x] Mining-site control and extraction, with tests for inventory transfer.
- [x] Production orders, labor, input/output and wage settlement.
- [x] Agent bridge tools for world queries, movement/travel and selected world-changing actions.

### Deployment and integration boundaries

- GitHub Pages is a static site. Deployment generates sample data; it is not a live simulation backend.
- Real-time ticking, writes and Agent execution require a separately run or deployed Rust API.
- Deployment files do not prove that a public service is operating.
- The root Cargo workspace and `engines/` are separate workspaces with different maturity and integration levels.
- PR CI, static-site deployment success, and a green CI run on the latest `main` are different release signals.

## Next priorities

### P0 — First-use experience and merge validation

- [ ] Verify root workspace, `engines/` workspace and container jobs on the latest `main`; resolve failures and long-running checks.
- [x] Explain the difference between the static demo and the separately hosted live API.
- [x] Let first-time visitors compare baseline and variant worlds and inspect metrics, locations, factions and events.
- [x] Support offline export of versioned comparison reports.
- [x] Cover report export/import, live-API travel/checkpoint export, and offline replay sharing in browser E2E tests.
- [ ] After recent benchmark-preflight and deployment-validation changes merge, rerun the full CI matrix.

Acceptance: a clean visitor can inspect the default world, compare rules and export a valid report without local setup or an API connection; limitations are clear; deployment and relevant CI checks pass.

### P1 — Stability and maintainability

- [x] Document SDK API stability levels and migration expectations; 0.1.x remains a preview API.
- [x] Add a versioned v1 envelope and JSON Schema for SDK checkpoints; unknown schema versions fail closed. Automatic cross-version migration is not promised.
- [x] Maintain replay-consistency and resource-ledger checks across multiple seeds and tick horizons.
- [x] Record release-mode performance baselines for synthetic worlds and save raw artifacts; calibrated performance regression thresholds are not yet established.
- [x] Document boundaries between travel supplies, location inventories, trade and production ledgers.
- [x] Provide task-level evaluation tooling for three Agent retrieval modes, including paired initial-state checks and reports.
- [ ] Run provider-backed Agent comparisons in an environment with explicit budget and real provider configuration. Offline tests do not establish that one retrieval mode is superior.

### P2 — Public live API service

- [x] Provide preflight checks for self-hosted API configuration.
- [x] Document HTTPS, authentication, health/readiness checks, backup, restore, token rotation and incident handling.
- [x] Add instance-level rate limiting for selected Agent, experiment, LLM-stream and session-driven routes.
- [ ] For public multi-user service, deploy on a real host/domain and validate user-level authorization, cross-instance quota coordination, centralized logs, alerts, and backup/restore.
- [ ] Exercise persistence degradation, concurrent writes, idempotency, credential rotation and recovery on a real deployment.
- [ ] Measure provider timeouts, quota limits, retries, streaming support and cost with the intended LLM provider.

## Non-goals and claim boundaries

- Reproducible simulation does not prove that rules match reality or enable real-world prediction.
- Comparing interventions inside the model does not prove real-world causal effects.
- Resource-ledger invariants are not physical conservation laws; travel risk scores are not calibrated probabilities.
- A 2.5D SVG location network is not a general-purpose 3D map engine.
- Causal graphs, memory retrieval and Agent tools do not by themselves constitute production-grade general intelligence or a security sandbox.
